## Core rules

- Treat GitHub as the authoritative source for project documentation, rules, architecture, registries, and history.
- Treat Canva as the authoritative source for editable visual designs.
- Do not create new categories, IDs, registries, or templates without checking existing rules and registries first.
- Preserve existing IDs and never reuse an ID for a different object.
- Register approved content and visual assets in the appropriate registry.
- When a conflict exists, follow the higher-level canonical document according to the hierarchy defined in `DOCS/ARCHITECTURE.md` and `DOCS/PROJECT_RULES.md`.

## Rule for updates

New project-wide rules must be recorded in the canonical documentation under `DOCS/` and, where applicable, reflected in the relevant registry or system documentation. Do not create a parallel authoritative documentation tree.
